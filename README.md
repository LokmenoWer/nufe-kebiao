# 南财课表（非官方）

官方网站：[https://kebiao.nufe.wiki](https://kebiao.nufe.wiki)

**南财课表**是面向南京财经大学学生的非官方课表工具。使用学校统一身份认证账号登录即可自动同步教务系统课表，无需手动录入。

本项目后端基于 `FastAPI`，前端采用无构建步骤、无框架依赖的原生 `ES Modules`：后端代登录统一身份认证（CAS）抓取教务课表并定时同步，前端按真实时间渲染周视图与日视图，并提供实时上课进度、`.ics` 日历订阅、邮件变动通知、iOS Scriptable 桌面小组件及安卓桌面小组件 App。

> 本项目为非官方第三方工具，与南京财经大学无隶属关系。代登录可能受学校信息系统使用条款约束，部署和使用前请自行评估。

## 功能

- **两种登录方式**：支持账号密码登录与学校统一身份认证扫码登录。学校的人机验证（图形验证码、滑块拼图）和二次认证（短信、动态口令）均转交用户本人完成，程序不识别、不代拖、不绕过。
- **周视图 + 日视图**：提供当前时间线、上课实时进度、下一节课提示、回到本周及按周/日深链接；移动端周视图支持横向滚动，时间轴固定在左侧。
- **原生现代前端**：基于无构建步骤的 ES Modules，采用原生 `dialog` / `popover` / `color-mix`，支持浅色、深色与跟随系统主题，移动端配备底部抽屉式设置页。
- **动态后台刷新**：不设固定时段和统一间隔，按用户活跃度与近期课表变动动态计算基础刷新间隔，并在每节课课前 30 分钟（出门前检查点）再次向教务系统确认；同班同学发现调课（含补课、加课）时优先联动刷新，同一节课已有同学刚确认过则跳过重复请求；全站请求预算随学校服务器响应自动伸缩，失败时按指数退避重试；登录态过期、需要验证码或二次认证时会在页面顶部提示并暂停自动重试。
- **登录态保活**：教务系统会话闲置约半小时即过期，且扫码登录获取的统一身份认证会话为短期会话（无“记住我”），因此后台默认每 20 分钟（`SSO_KEEPALIVE_MINUTES`）自动访问一次认证中心与教务系统以维持登录态；预算紧张时优先保障扫码登录及未保存密码的用户（处于失败退避期仍继续保活，超过 `SSO_KEEPALIVE_IDLE_DAYS` 即 14 天未访问本站则暂停保活），且仅使用刷新剩余预算。扫码登录用户在课表页顶部可查看保活说明（可关闭），当认证中心登录态失效时会收到常驻提醒，设置页也会实时展示登录保活状态。
- **邮件通知**（可选）：绑定邮箱后，当后台自动刷新暂停（需重新登录或填写验证码）、连续刷新失败或检测到课表变动时自动发送邮件提醒；两类提醒可独立开关。
- **iOS 桌面小组件**（Scriptable）：在桌面和锁屏展示今天、明天或本周课程，高亮正在上课与下一节课，并在无课时预告下次上课时间。
- **安卓 App 与桌面小组件**（`android/`，Jetpack Glance）：提供“今天”（课后自动切换为明天）和“本周”两种桌面小组件，支持自由拉伸尺寸、实时上课倒计时、下次上课预告、调课标记、本机课前提醒及灵动显示（支持 Android 16+ 原生 Live Updates / ColorOS 16 流体云等系统实时通知，并提供主流定制系统的实验性通知扩展，受白名单限制时自动回退为常驻倒计时卡片）。
- **日历订阅**：生成可随时撤销的 `.ics` 订阅链接，支持 iOS / macOS 日历、Google 日历、Outlook 等客户端，并可通过 `?alarm=分钟` 参数附加课前提醒。
- **安卓日历桌面方案（免装专用 App）**：通过开源应用 ICSx⁵ 订阅 `.ics` 链接将课表同步至系统日历，即可直接使用系统日历桌面小组件与系统日历提醒。
- **数据自主可控**：支持随时删除已保存的密码，或一键注销账号并清除全部数据。

## 快速开始

环境要求：Python 3.10+。

```bash
uv venv .venv && uv pip install -p .venv -r requirements.txt
cp .env.example .env    # 填写 APP_SECRET_KEY（生成密钥的命令见 .env.example）
```

### 1. 命令行验证登录与抓取课表

```bash
.venv/bin/python -m app.cli 你的学号 -o my.json
# Windows: .venv\Scripts\python.exe -m app.cli 你的学号 -o my.json
```

密码通过交互式终端输入，不回显、不落盘。成功后会打印 `登录成功` 及本学期课程列表，并将规范化后的 JSON 写入 `my.json`。

- 遇到**图形验证码**时：验证码图片会保存到临时目录并自动打开，由你本人输入。
- 遇到**手机短信二次认证**时：按回车发送短信，再输入收到的短信验证码。
- 附加 `--dump debug/` 参数可将登录每一步的落地页（URL + HTML，不含密码）保存至本地，便于在学校页面改版时排查问题。

### 2. 启动 Web 服务

```bash
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers
# Windows: .venv\Scripts\uvicorn.exe app.main:app --host 127.0.0.1 --port 8000 --proxy-headers
```

生产环境建议置于 Caddy / Nginx / Apache 反向代理后启用 HTTPS，并将 `PUBLIC_BASE_URL` 设为 `https://...`，系统会自动开启 Secure Cookie、HSTS 及 HTTP→HTTPS 跳转。由于后台刷新线程在进程内运行，**请仅启动单进程 worker**（不要使用 `--workers N`）。

### 离线演示（不访问学校服务器）

```bash
.venv/bin/python scripts/demo_server.py   # http://localhost:8765
# Windows: .venv\Scripts\python.exe scripts/demo_server.py   # http://localhost:8765
```

使用 `examples/sample_timetable.json`（脱敏示例数据）启动完整前端演示：账号密码登录可填写**任意学号 + 密码 `demo`**；扫码登录点击“显示登录二维码”后会在几秒内自动确认。密码分别填写 `captcha` / `slider` / `sms` / `otp` 可依次体验图形验证码（输入 `abcd`）、滑块拼图、短信验证与动态口令二次认证。演示模式已放宽登录限流，便于前端开发与联调。

### 3. 运行测试

```bash
.venv/bin/python -m pytest -q        # 后端 / API 测试（上游请求全部打桩）
node --test tests/js/*.test.js       # 前端纯逻辑测试（Node 20+，无需安装 npm 依赖；Windows 相同）
uv pip install -p .venv ruff         # 可选：Python 静态检查
.venv/bin/ruff check app tests scripts
# Windows: .venv\Scripts\python.exe -m pytest -q
#          .venv\Scripts\ruff.exe check app tests scripts
```

所有测试均对上游（CAS / 教务系统）打桩，不会访问学校服务器。前端测试覆盖日期与周次计算、重叠课程分道排版、课程配色与节次兜底、URL hash 解析及 Scriptable 小组件排版；浏览器端交互可通过离线演示服务器验证。

## 前端架构

前端位于 `static/` 目录，**无需打包构建、无需 Node 运行时**，部署时随 Python 代码一同同步即可：

```
static/
  index.html          # 页面模板（{{assets}} / {{modulepreload}} 由后端注入）
  css/
    tokens.css        # 颜色、圆角、阴影设计令牌与深色主题
    base.css          # 基础重置、按钮、表单、提示条、骨架屏
    layout.css        # 顶栏、登录页、工具栏、页脚
    timetable.css     # 周视图网格、日视图、移动端横向滚动
    dialogs.css       # 确认弹窗、课程详情、设置抽屉
  js/
    main.js           # 会话恢复、登录页与课表页切换
    api.js            # CSRF 令牌、错误提示、超时控制、401 处理
    dom.js icons.js    # 无 innerHTML 的 DOM 构造工具与内联 SVG 图标
    time.js courses.js overlap.js hash.js store.js theme.js
    components/       # toast / dialog / slider-captcha
    views/            # login / timetable / settings（含邮件、小组件、安卓子模块）
```

设计要点：

- **CSP 友好**：页面无任何内联脚本或内联样式，所有 DOM 节点均通过 `textContent` / `setAttribute` 构建；服务端 CSP 额外启用 `require-trusted-types-for 'script'`。
- **免构建内容哈希与长缓存**：访问 `/` 时动态渲染 `index.html`，静态资源路径重写为 `assets/<static/ 全部资源内容哈希>/…`。由于版本号位于路径前缀中，ES 模块间的相对 `import` 会自动携带同一版本前缀，全套 CSS/JS 均设置 `max-age=1年, immutable`，二次访问无需重复请求；页面同时注入全量 `modulepreload`，使首次访问并行下载模块而非逐层串行加载。页面与静态资源启用 gzip 压缩（`/api` 不压缩，防范 BREACH 攻击）。修改前端代码后直接刷新浏览器即可生效，无需重启 Python 进程；不带版本号的 `/static/` 路径仍保留协商缓存，为发版前已打开的旧页面兜底。
- **深链接（Deep Link）**：当前学期、周次、视图模式与所选日期实时同步至 URL hash，刷新或分享链接不会丢失浏览位置。例如：
  - `#sem=161&w=8&view=week`
  - `#sem=161&w=8&view=day&d=2`
- **键盘快捷键**：`←` / `→` 切换周次（日视图下切换日期）、`T` 回到本周、`W` / `D` 切换周/日视图；焦点位于输入框或弹窗内时自动跳过拦截。
- **响应式视图**：桌面端与移动端均支持周视图与日视图切换；移动端周视图支持横向滚动（列宽 ≥96px），时间轴与星期表头分别固定在左侧和顶部。
- **模板文件保护**：直接请求 `/static/index.html` 或 `/static/admin.html` 会返回 404，防止暴露未替换占位符的原始模板。

Node.js 仅用于执行 `node --test` 单元测试，`package.json` 不包含任何第三方依赖。

## 部署到生产服务器

```bash
cp deploy/deploy.env.example deploy/deploy.env   # 填写 HOST / SSH_KEY / PUBLIC_BASE_URL（该文件已加入 .gitignore）
deploy/deploy.sh
```

- 代码同步至 `/opt/nufe-kebiao`，由 systemd 服务 `kebiao` 托管（运行用户 `kebiao`，仅监听 `127.0.0.1:8010`，单 worker 进程）。
- **平滑重启不停服**：`127.0.0.1:8010` 套接字由 `kebiao.socket` 持有，重启服务期间新请求会在内核队列中等待新进程接管（通常在 1 秒以内），不会拒绝连接；正在处理的请求最长等待 5 秒优雅退出。反向代理配置中需为 `ProxyPass` 加上 `retry=0`（示例配置已包含），避免 Apache 因瞬时连接失败而在接下来 60 秒内直接返回 503。
- 服务器上的 `.env`（含首次自动生成的 `APP_SECRET_KEY`）和 `data/` 目录仅在首次部署时创建，后续部署不会覆盖。
- **反向代理示例（Apache）**：推荐使用独立域名，`deploy/apache-kebiao.conf` 提供了完整虚拟主机配置（80 跳转 443、全站反代至 8010、访问日志自动忽略含 token 的路径）。也支持挂载在子路径下（如 `PUBLIC_BASE_URL=https://example.com/kebiao`，Cookie Path 会随之设为 `/kebiao/`），前端请求均采用相对路径；若后续从子路径迁移至独立域名，可将旧虚拟主机改为引入 `deploy/apache-kebiao-legacy.conf`，使网页请求 301 跳转至新域名，同时保持已发放的日历订阅和小组件链接原地可用。
- 查看实时日志：`journalctl -u kebiao -f`
- 查看后台刷新调度状态：`journalctl -u kebiao | grep "tick:"`——当有用户到期、执行刷新或预算发生变化时，每轮 tick 会输出一行摘要，例如 `tick: due=12 refreshed=8 budget=0.65/s (max 0.65)`；因学校服务器报错触发预算减半时也会明确记录。
- 健康检查：`GET /healthz` 返回 `{"ok": true}`。
- **服务器管理后台** `/admin`：集中展示待处理告警、实时在线人数（统计 5 分钟内有请求的登录用户与独立 IP 访客，按网页、iOS 小组件、安卓 App、日历订阅分渠道汇总，并提供 1 小时 / 24 小时 / 7 天活跃统计）、用户与刷新统计（含手机代抓占比）、后台刷新排期（展示每位用户的下次刷新时间、触发原因、手机代抓等待状态、全站预算及学校服务器健康度，支持按状态筛选或手动将指定用户排入队首）、手机与安卓管理（代抓统计、已绑定设备、安装包镜像与 GitHub 同步状态）、全站刷新记录（支持按来源与失败状态筛选）以及进程内最近 2000 条实时日志（支持按级别与关键字检索）。所有学号与姓名均脱敏展示。
  - 管理员密码仅以 PBKDF2 哈希形式保存在服务器 `.env` 的 `ADMIN_PASSWORD_HASH` 中；未配置时整个管理后台返回 404。可通过 `.venv/bin/python -m app.admin hash` 生成密码哈希，填入 `deploy/deploy.env` 后运行 `deploy/deploy.sh` 即可同步至服务器（仅传输哈希值）。
  - 管理员会话保存在进程内存中，有效期 12 小时，服务重启后需重新登录；登录接口按 IP 限流（每 15 分钟最多 5 次）。

> 订阅链接与小组件链接中的 token 即为访问凭证。应用已对自身 uvicorn 访问日志中的 `/ics/`、`/widget/`、`/mobile/` 路径做 `<redacted>` 脱敏；若反向代理、CDN 或云厂商日志仍会记录完整 URL，请自行对上述路径配置脱敏或忽略记录。

## 登录链路说明

1. `GET /student/for-std/course-table`：未登录时**先落到教务系统自身的 `/student/login`**，不会直接跳转 CAS。
2. `GET /student/sso/login` → 302 跳转至 `authserver/login?service=https://jwxt.nufe.edu.cn/student/sso/login`，该 URL 即为后续表单 POST 的目标地址。
3. 从 `#pwdFromId` 表单提取 `pwdEncryptSalt` / `execution` / `lt`（页面共有 5 个表单，`execution` 通常为 `e1s1`）。
4. 请求 `checkNeedCaptcha.htl`：若要求填写验证码则暂停并交由用户完成，不尝试自动识别或绕过。验证类型由登录页的 `captchaSwitch` 决定：
   - `1` 图形验证码 → 进入 `captcha` 阶段：将 `getCaptcha.htl` 返回的图片原样展示给用户，用户填写后随登录表单一并提交；
   - `2` 滑块拼图 → 进入 `slider` 阶段（兼容 `ids-sliderCaptcha.js` / `longbow.slidercaptcha.js`）：调用 `common/openSliderCaptcha.htl` 获取背景图与拼图块，前端按学校插件一致的 280×155 坐标系渲染，**由用户本人拖动滑块**；采集到的位移与轨迹（采样规则与原插件一致，小屏缩放后自动换算回 280 宽坐标）使用拼图块末尾附带的 16 位密钥加密为 `sign`，POST 至 `common/verifySliderCaptcha.htl`，返回 `errorCode=1` 后再提交账号密码。每张拼图仅校验一次，失败自动刷新图片，签名密钥仅保留在服务端内存中。
5. POST 提交加密后的密码（`randomString(64)+pwd`，采用 AES-CBC 加密，`key=salt`，随机 IV 无需回传）。
6. 若跳转至二次认证页（`reAuthCheck` / `isMultifactor=true`），按页面特征自动匹配验证方式：
   - 手机短信（`reAuthType=3` 或包含 `dynamicCode` 输入框）：调用 `dynamicCode/getDynamicCodeByReauth.do` 下发短信 → 调用 `reAuthCheck/reAuthSubmit.do` 提交 `dynamicCode`；
   - 动态口令（包含 `otpCode` 输入框，即身份验证器 App）：将用户输入的口令填入 `otpCode` 提交；
   - 其他方式（如密保问题、邮箱验证、App 扫码确认等）暂不支持转发：立即终止流程并告知用户具体验证类型，建议改用扫码登录。
   验证通过后再次访问登录地址获取 ticket。接口路径优先从页面脚本中动态解析，并严格校验域名仍在 `authserver.nufe.edu.cn` 下。
7. 获取 `CASTGC` 后再次访问教务课表页，解析 `personId` 与 `currentSemester`，最后调用 `print-data` 接口拉取课表数据。

**扫码登录**（兼容 `qrcode.js`）：调用 `qrCode/getToken` 获取 uuid → 请求 `qrCode/getCode?uuid=` 获取二维码图片 → 后台线程在遵循上游节流的前提下轮询 `qrCode/getStatus.htl`（1=已确认，2=已扫描，3=已失效），前端每 2 秒仅读取本站内存状态 → 手机确认后按 `#qrLoginForm` 字段 POST 提交至 `login?display=qrLogin&service=…`，后续流程与账号密码登录一致（可能触发短信二次认证）。扫码登录全程不接触密码，也不会修改用户已有的凭据保存设置；学号从教务系统返回的数据中提取。单次登录流程前端最多轮询 120 次、刷新二维码最多 10 次，且不会无限延长 5 分钟的流程有效期。

**站点会话有效期**：登录时勾选“保持登录 180 天”将下发持久化 Cookie（`SESSION_DAYS_LONG`）；未勾选则使用浏览器会话 Cookie，服务端最长保留 `SESSION_DAYS_SHORT`（默认 7）天。两者均采用**滑动续期**机制：每次访问页面（每天最多触发一次）自动顺延有效期，常用用户不会因首次登录满 N 天而被强制登出。

**学校登录态续期**：当教务系统会话过期时，服务端优先使用统一身份认证的 `CASTGC`（账号密码登录默认携带 `rememberMe=true`）静默执行 SSO 续期；仅当 `CASTGC` 亦失效或认证中心要求二次认证时，才提示用户重新登录（已勾选保存密码的用户此时会使用加密保存的密码自动重登）。

所有人机验证与二次认证均**严格转交用户本人完成**（网页端展示验证码图片、滑块拼图或验证码输入框；CLI 支持图形验证码、短信和动态口令，滑块验证请使用网页端），程序不做任何自动识别或绕过。未完成的登录流程仅暂存于进程内存中，5 分钟后自动过期；单个流程最多发送 3 次短信、尝试 5 次验证。后台定时刷新无真人在场，遇到人机验证或二次认证会立即停止自动重试，并在界面提示用户重新登录。

## 凭据与安全设计

| 模块 | 安全实践 |
|---|---|
| 站点账号 | 不设独立站点密码：登录本站即实时通过学校 CAS 验证，首次登录成功自动建号，数据库中不存在可供撞库的站点密码哈希 |
| 默认凭据 | **默认仅保存 CAS 登录态 Cookie**（含 TGC；账号密码登录附带 `rememberMe=true`，扫码登录与学校原生表单一致不带），采用 AES-256-GCM 加密落库；过期后标记为 `needs_rebind`，用户重新登录即可续期 |
| 可选保存密码 | 仅在用户主动勾选并阅读风险提示后保存，同样使用 AES-256-GCM 加密。后台刷新时**优先尝试 Cookie 续期**，仅在 Cookie 失效时才解密密码重新登录；可在设置页一键删除已保存的密码 |
| 加密密钥 | `APP_SECRET_KEY`（32 字节，服务启动时强制校验 Base64 格式与长度）。加密时通过 AAD 绑定 `用途:用户id`，防止密文跨行替换；接入 KMS 时将解密后的数据密钥注入该环境变量即可 |
| 损坏数据兜底 | 密文或课表 JSON 损坏时自动标记 `needs_rebind` 或隐藏异常学期，不会向客户端抛出 500 内部错误；原始异常信息不写入日志、不返回浏览器 |
| 日志脱敏 | 严禁记录密码与 Cookie；异常日志仅记录异常类型；uvicorn 访问日志对 `/ics/`、`/widget/`、`/mobile/` 路径中的 token 自动脱敏；`urllib3` 日志级别调至 WARNING |
| 会话 Cookie | 采用高熵随机 token，数据库仅存储 SHA-256 哈希；Cookie 启用 `HttpOnly; SameSite=Lax; Secure(https)`；每位用户最多保留最近 8 个活跃会话 |
| CSRF 防护 | 所有写请求强制校验 `Origin` / `Referer`（当 Referer 被浏览器隐私策略剥离时使用 `Sec-Fetch-Site` 兜底，同时防范登录 CSRF），且已登录写接口必须携带匹配的 `X-CSRF-Token` |
| 安全响应头 | 启用严格 CSP（禁止内联脚本，限制 `base-uri` / `object-src` / `form-action`，开启 Trusted Types）、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`（防止订阅 token 通过 Referer 外泄）以及 CORP / COOP |
| 前端防 XSS | 绝不拼接 HTML 字符串（不使用 `innerHTML` / `eval`），所有来自用户或教务系统的数据均通过 `textContent` 写入；自动化测试会静态扫描全部前端源码以防引入危险写法 |
| 通知邮箱 | 需用户主动绑定并通过 6 位邮件验证码确认（数据库仅存验证码 HMAC，10 分钟有效、最多尝试 5 次、重发间隔 60 秒）；邮箱地址采用 AES-256-GCM 加密存储；验证邮件与测试邮件按每用户 5 封/小时、每 IP 10 封/小时限流，防止邮件轰炸；日志中仅输出打码后的邮箱地址 |
| 数据销毁 | 设置 → “删除我的账号与所有数据”，通过外键级联删除会话、课表、刷新记录、订阅/小组件 token、绑定设备及通知邮箱，并同步清理内存中的登录流程与缓存 |

### 邮件通知

在 `.env` 中配置好 SMTP 参数后，设置页会自动显示“邮件通知”模块（未配置时自动隐藏）：

```
MAIL_MAILER=smtp            # 设为 log 时不实际发信，仅输出到日志（用于本地开发与演示）
MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_USERNAME=you@163.com
MAIL_PASSWORD=<邮箱的 SMTP 授权码，非邮箱登录密码>
MAIL_ENCRYPTION=ssl         # ssl（465）| tls（587，STARTTLS）| none
MAIL_FROM_ADDRESS=you@163.com
MAIL_FROM_NAME=南财课表
```

- 邮件通过单线程后台队列异步发送，SMTP 响应缓慢或连接失败不会阻塞网页访问与课表刷新；发送失败最多重试两次，两封邮件之间至少间隔 `MAIL_MIN_INTERVAL`（默认 3）秒。
- 仅在**后台自动刷新**触发时发送提醒（手动刷新或登录时用户已在屏幕前，不重复发信）：
  - **刷新暂停提醒**：当账号状态首次变为需要重新登录或需要填写验证码时发送一封；普通网络/上游错误在连续失败次数恰好达到 `REFRESH_MAX_FAILS` 时发送一封，避免每次失败重复打扰。
  - **课表变动提醒**：与同一学期上次保存的课表对比（课程名、星期、节次与时间、上课地点、周次），在邮件中列出新增与取消的排课条目。首次同步课表不计为变动。
- 每封通知邮件末尾均附有退订说明，用户可随时在设置中关闭对应提醒或解绑邮箱。

### 安卓 App 与个人信息保护

设置 → “安卓 App”：生成配对链接 → 点击“在安卓 App 中打开”或复制配对链接到 App 中粘贴。App 课表数据读取自 `GET /mobile/<token>.json`，**响应中不包含姓名、学号、学院、专业、班级、邮箱等个人身份信息**；即使课表链接不慎外泄，他人也只能看到课程安排，无法获取个人信息或代抓任务中的教务会话（代抓任务需验证设备私钥签名后才会下发）。iOS 小组件使用的 `/widget/<token>.json` 同样不含个人信息，且仅凭链接无法领取代抓任务（需校验脚本内的代抓密钥）。

- **设备绑定**：App 在系统硬件级 Android Keystore 中生成不可导出的 P-256 密钥对；网页端签发 10 分钟有效、单次使用的一次性配对码（`POST /api/mobile/pair`，数据库仅存哈希），App 凭配对码调用 `POST /mobile/<token>/pair` 注册设备公钥。仅持有课表链接而无配对码无法绑定设备。每位用户最多绑定 5 台设备；若已绑定通知邮箱，新增设备绑定时会收到邮件提醒。
- **读取个人信息**：调用 `GET /mobile/<token>/profile` 时，请求头需携带设备 ID、时间戳与 ECDSA-SHA256 私钥签名（签名原文为 `nufe-kebiao-device-v1\n<token>\n<设备 id>\n<时间戳>`），服务端允许的时间戳偏差不超过 5 分钟，并在签名校验失败时返回 `server_time` 供手机自动校准时钟偏差。该接口禁止缓存，且仅返回打码后的邮箱地址；App 收到后使用 Keystore 中的 AES-GCM 密钥加密持久化至本地。
- **手机端代抓课表**：已绑定的安卓 App 在请求 `/mobile/<token>.json` 时同样携带设备签名，服务端验证通过后才会在响应 JSON 中下发 `fetch` 代抓任务（及 `poll_after` 建议轮询间隔）；App 使用手机自身的网络直接向教务系统拉取原始课表页面，并通过 `POST /mobile/<token>/upload` 原样交回服务端解析入库；若手机端拉取失败则如实上报，由服务端兜底刷新。未绑定设备或仅持有链接的客户端不会收到代抓任务，任务中的教务 Cookie 亦不会写入 App 本地缓存。设置页中的“用这台手机的网络直接向学校获取课表”开关同时控制 iOS 小组件与安卓 App。
- **撤销与挂失**：可在设置页查看并随时撤销已绑定设备（`/api/mobile/devices`）；撤销后该设备无法再读取个人信息或领取代抓任务，但原有链接仍可读取课表。若手机丢失或链接泄露，请点击“重新生成”或“停用”，使旧链接、所有已绑定设备及未使用的配对码立即全部失效。
- **安全边界说明**：若手机已被 root 或被恶意软件完全控制，本机存储的数据仍可能面临风险；此外，课表中的课程组合、任课教师与教室信息本身也可能间接暴露所在专业或班级，若链接泄露请及时重新生成。

### 安卓安装包镜像

为方便无法直连 GitHub 的用户下载与更新 App，服务端内置了免登录、全自动同步的安装包镜像服务：

- `GET /android/releases.json`：每 30 分钟同步一次 GitHub Releases（保留最新 5 个版本），返回格式与 GitHub API 保持一致；当 GitHub 暂时不可达时继续返回已缓存的版本列表。安卓 App 检查更新时优先请求 GitHub，连接失败时自动切换至本站镜像。
- `GET /android/apk/<版本>.apk`：首次有用户请求时按需下载至服务器 `data/android-apk/` 目录，严格校验 GitHub Release 提供的 SHA-256 摘要后才向客户端分发，旧版本下架后自动清理。访问 `GET /android/latest.apk` 会直接跳转至最新正式版安装包。
- 部署服务器需具备访问 GitHub 的网络条件，否则新版本无法同步至镜像（已缓存的旧版本仍可正常使用）。安卓系统在覆盖安装时也会强制校验 APK 签名一致性，确保更新安全。

### iOS 桌面小组件（Scriptable）

设置 → “iOS 桌面小组件”：生成小组件链接 → 点击“复制脚本”（脚本内已自动填入你的专属链接与代抓密钥）→ 粘贴到免费的 [Scriptable](https://apps.apple.com/cn/app/scriptable/id1405459188) 应用中 → 在桌面添加 Scriptable 小组件并选择该脚本。小组件 `Parameter` 参数可填写 `today`（默认，今天）/ `tomorrow`（明天）/ `week`（本周，按节次）/ `full`（也可填 `铺满`，按时长铺满），参数后可追加课前提醒分钟数（如 `today 15`、`week 20`；填 `today 0` 关闭提醒，不填默认提前 10 分钟）。也可在 Scriptable 内直接运行脚本 → 点击“提醒时间”进行设置（若 `Parameter` 中填写了数字，以 `Parameter` 为准）。

- **数据源**：通过 `GET /widget/<token>.json` 获取数据。服务端按北京时间预先计算今天、明天、本周（以及未来两周内下一个有课日）的排课，周次推算、缺失时间兜底、课程配色均与网页端和 `.ics` 日历保持一致，Scriptable 脚本仅负责渲染排版。
- **凭证隔离**：小组件 token 与 `.ics` 日历订阅 token 相互独立，可单独重新生成或停用；数据库仅存 SHA-256 哈希，访问日志对 `/widget/` 路径自动脱敏，删除账号后立即失效。
- **一键订阅到系统日历**：在 Scriptable 内运行脚本并选择“订阅到日历”，脚本会调用 `POST /widget/<token>/calendar` 获取你的 `.ics` 订阅链接（若尚未生成则自动创建，若已存在则直接返回原链接，不影响其他设备已添加的日历订阅），随后通过 `webcal://` 唤起 iOS 系统日历完成订阅。
- 脚本源码位于 `scriptable/nufe-kebiao-widget.js`，支持小号、中号、大号、超大号桌面小组件及三种锁屏小组件，涵盖以下特性：
  - **上课中与课间状态**：正在上课的课程展示距下课实时倒计时（由系统原生计时组件驱动，每秒自动跳动，不依赖小组件刷新），下一节课展示“X 分钟后”；
  - **课后、周末与假期预告**：当天课程全部结束后、周末或假期自动预告下次上课安排；**开学前**显示“距开学还有 N 天”，**结课后**显示“本学期课程已结束”；
  - **week（按节次）模式**：还原标准教务课表布局——纵轴按节次等高排列，课程卡片从起始节延伸至结束节（2 节课与 4 节课的高度一目了然），左侧时间轴在每节课顶边旁标注准确的开始时间（空间充足时附注“第几节”），开始时间相近的不同节次（如 08:20 / 09:05、13:30 / 14:15）各自独立成行，不会合并重叠；仅当多门课在同一时段真正冲突时才标记为“+1”，其余课程均完整展示；停课课程在原位置标记“停”。若部分课程缺少节次信息，优先参考同周其他课程补齐，无法补齐时自动切换为按真实时间轴排版。周一至周五固定展示，周末仅展示到最后一个有课日；到了周末且本周剩余时间无课时，自动切换展示下周课表；
  - **full（铺满）模式**：同样展示本周或下周课表，纵轴按真实课程时长比例分配高度，并将全周无人上课的空闲时段（如午休、傍晚）折叠为 6pt 间距，让课程卡片充分利用整块小组件空间；
  - **自适应内容排版（week / full 共用）**：卡片高度优先保障每节课的核心信息完整显示——起止时间、完整课程名、教室编号（教学楼名与教师姓名在空间允许时展示），剩余纵向空间再按节次数（week）或课程时长（full）按比例分配；字数较多的短课会自动获得更多高度，各天同一节次的分界线依然严格对齐。排版引擎依次尝试 1 / 0.9 / 0.8 倍字号，仍放不下时才逐级精简次要信息（先省教学楼名，再省下课时间）；对于开始时间已标在左侧时间轴上的窄列卡片，卡片内时间简化为“–09:45”以节省一行高度。中号小组件纵向空间有限（约 85pt），周课表仅展示课程名与教室，建议大号小组件使用 `week` / `full` 模式。修改版面逻辑后可运行 `node scripts/widget_preview.mjs`，在终端查看各尺寸与模式下的文字截断统计，并在浏览器中打开生成的预览页（溢出文字会以红色高亮）；
  - **按机型精确计算尺寸**：`week` / `full` 模式通过 `Device.screenSize()` 对照 Apple 官方小组件尺寸表（覆盖各代 iPhone 与 iPad）计算当前设备的小组件宽高；未知新机型或开启“放大显示”时自动匹配最接近的尺寸并按比例缩小，避免内容溢出；
  - **点击直达**：点击小组件可打开网站对应日期的日视图或对应周次的周视图；在中号、大号小组件中点击具体课程或某一天所在列，可直接跳转到当天日视图；
  - **异常与离线提示**：学校登录态失效时显示“需重新登录”，课表超过 2 天未同步时提示“N 天未更新”，无网络时自动读取本地缓存并标注“离线”；
  - **多账号缓存隔离**：每个小组件链接对应独立的本地缓存文件，多账号共存互不覆盖；
  - **脚本在线更新**：`/widget/<token>.js` 支持凭同一只读 token 拉取最新脚本；当服务端脚本升级后，小组件标题栏会提示“脚本可更新”，在 Scriptable 中运行脚本并点击“更新脚本”即可原地升级（校验下载内容确属本人脚本后才写入，并自动保留本机代抓密钥）。在应用内运行脚本还支持预览各尺寸效果与快捷打开网站；
  - **调课与停课标记**：服务端自动记录最近 7 天检测到的调课记录（对比变更前后的排课安排），按具体日期比对后在 JSON 中标注 `changed` / `was`（如“原 A101”“原 10:00”），并将当天整门停上的课程放入 `cancelled`（将“1~16 周”拆分为“1~8,10~16 周”等调整不会误标未受影响的其他周次）。小组件上变动课程会标记“调”并附上原安排，停课单独成行展示，标题栏同时提示“有调课”；
  - **手机代抓课表（默认开启，可在设置中关闭）**：当课表到达刷新时机时，服务端会向携带有效代抓密钥（请求头 `X-Widget-Key`）的脚本下发 `fetch` 任务，由脚本**使用手机本地网络**直接请求教务系统课表页与 `print-data` 接口（必要时附带学期详情），再将原始响应 POST 至 `/widget/<token>/upload`；服务端使用同一套解析逻辑入库（刷新记录中标记为“手机代抓”），并在响应中直接返回最新小组件数据，使当次刷新立即渲染新课表。代抓密钥由主密钥与 token 派生（`crypto.widget_fetch_key`），仅在已登录状态下从设置页点击“复制脚本”时注入，公开的 `/widget/<token>.js` 接口不包含该密钥；若小组件提示“请重新复制脚本”，重新从设置页复制粘贴一次即可恢复手机代抓；
  - **刷新与节流协同**：每次小组件刷新仅请求一次 `GET /widget/<token>.json`（有代抓任务时附加教务请求）。临近上课前的课表确认由服务端“出门前检查点”统一调度，当数据超过目标间隔时服务端自动排入刷新队列，小组件标题栏显示“更新中”并将下次重绘时间提前至约 2 分钟后。在 Scriptable 内运行脚本选择“刷新课表”会发送 `?refresh=1` 请求排入队首（若 2 分钟内刚同步过或需重新登录则直接跳过），实际访问学校服务器仍受全站预算约束；
  - **本机上课提醒**：根据未来 7 天课表在手机本机注册本地通知（含课程名、时间、教室；调课课程会注明“已调课”及原安排），默认提前 10 分钟提醒，最多注册 40 条。由于 iOS 小组件后台进程调用通知接口容易超时被系统终止（导致桌面显示 `Call Script.setWidget()`），本地通知统一在 Scriptable 应用内运行脚本时排期与更新：小组件在桌面刷新时会将 `Parameter` 中的提醒分钟数写入本机状态文件（位于 Library 目录下按站点命名的 `.state.json`），后续在 Scriptable 中运行脚本时即按该分钟数排期。提醒分钟数优先级为：`Parameter` 参数 > 本机状态文件（小组件记录值或脚本菜单“提醒时间”所选值）> 上次排期使用值 > 默认 10 分钟。当服务端检测到新调课或用户修改了提醒分钟数时，小组件标题栏会提示“点按更新提醒”，点击小组件即可跳回 Scriptable 自动重排通知；
  - **重绘时机**：日常会在下一次上下课时刻、课前 37 分钟（开启手机代抓时由手机主动向教务确认）、课前 25 分钟（获取服务端课前 30 分钟确认后的结果）、每日零点或最长 30 分钟后请求系统重绘（具体触发时刻由 iOS 系统调度决定）。
- **脚本版本自动同步**：脚本模板中使用占位符 `__SCRIPT_VERSION__`，服务端下发脚本时自动替换为模板内容哈希 `sha-<12 位>`，并在小组件 JSON 的 `script_version` 字段中返回同一哈希；修改脚本并部署后，客户端比对不一致即提示“脚本可更新”。
- **自动化测试**：`tests/js/scriptable-shim.js` 提供了轻量级 Scriptable 运行时模拟环境，执行 `node --test tests/js/*.test.js` 即可在 Node.js 中对各尺寸和模式下的脚本渲染逻辑进行完整测试。

## 对学校服务器的节流与保护

- **优先使用学生手机网络代抓**：后台定时刷新的主要流量交由 iOS 小组件与已绑定的安卓 App 在学生手机端完成（`service.widget_fetch_task` / `accept_widget_upload`），教务系统看到的是学生分散的移动端 IP，大幅降低本站服务器 IP 的访问频率与被封禁风险。
  - **为何网页端无法代抓**：学校 `authserver` 与 `jwxt` 均未配置任何 CORS 响应头（跨域预检直接返回 403），浏览器网页中的脚本无法跨域读取学校响应；同时，首次登录（含验证码、滑块、短信、扫码）获取的会话 Cookie 必须保存在服务端才能支撑后续后台续期，因此登录流程仍由服务端转发。而 Scriptable 与安卓 App 发起的是原生 HTTP 请求，不受浏览器同源策略限制。
  - **最小权限与防伪造**：代抓任务仅在该用户**已到达刷新时机**（由同一套动态刷新策略判定并已进入队列）时签发，同一时刻仅存在一个有效任务，有效期 5 分钟且仅限提交一次；任务中仅下发教务系统域名（`jwxt`）的会话 Cookie，**统一身份认证的核心凭据 `CASTGC` 绝不离开服务器**。手机回传的新 Cookie 仅允许更新已有的教务 Cookie 键值，拒绝注入未知 Cookie 名称或其他域名。
  - **服务端礼让与兜底**：代抓任务下发后的 5 分钟内服务端不会重复抓取；对于最近 24 小时内手机代抓成功且未出错的用户，刷新到期后服务端会优先等待手机端完成——主动触发的刷新等待 10 分钟，常规基础间隔等待 45 分钟，出门前检查点等待至课前 32 分钟（检查点前 2 分钟）。开启代抓的小组件与安卓 App 会在课前 37 分钟主动唤醒并向教务系统确认课表。
  - **失败自动回退**：若教务会话过期（被重定向至登录页）、学校服务器报错、手机无网络、上传内容解析失败或发生学期切换，手机端均会如实上报，服务端立即接管并执行常规刷新（`CASTGC` 静默续期或解密密码重登均仅在服务端执行）；若代抓任务超时未回传也计为一次失败，此后服务端不再等待该手机，直至其下次主动代抓成功。
  - **凭证安全提示**：开启手机代抓后，持有小组件脚本或已绑定设备的客户端可获取教务系统会话；若怀疑脚本或链接泄露，请及时重新生成链接，或在设置中关闭“用这台手机的网络直接向学校获取课表”。
- **全局礼貌会话（`PoliteSession.send`）**：服务端发往学校的所有请求（含每次 302 重定向跳转）均经过统一节流器——**全站任意两次上游请求的发起间隔 ≥ 1 秒**（`UPSTREAM_MIN_INTERVAL` 最小为 1.0 秒），额外附加 0–0.2 秒随机抖动，且最大并发数不超过 2。高并发时请求在进程内排队等待，而非直接拒绝用户。
- **两层动态刷新策略**（`app/refresh_policy.py` + `app/scheduler.py`）：摒弃固定时段与一刀切轮询间隔。临时调课最关键的确认时机是**学生动身前往教室之前**，因此刷新时机由以下两层共同决定（取更早到期者）：
  - **出门前检查点**：以每节课开课前 30 分钟作为检查点，要求在检查点前 10 分钟窗口内（即课前 40～30 分钟）必须完成一次课表确认（根据本地已存课表推算下一节课，不额外请求学校）。若同一教学班（同一 `slot`）的同班同学在该时间窗口内已完成刷新且未发现调课，则视为已替全班完成确认——几十人的班级仅需向教务系统发起一次请求。该检查仅针对最近 14 天内活跃或已开启课表变动邮件通知的用户；
  - **基础刷新间隔**：根据用户活跃度（最近一次打开网页、小组件或拉取日历订阅的时间）分档——3 天内活跃每 4 小时、14 天内活跃每 6 小时、60 天内活跃每 1 天，更久未活跃每 1 周（若本周有课则至少每天刷新一次）；若最近 3 天内检测到调课则间隔减半；若未来 7 天内无课（假期、开学前、结课后）则放缓至至少每天一次；最短间隔下限为 15 分钟。每日凌晨（北京时间 0:00–6:30）教务系统无排课变动，常规基础刷新自动推迟至 6:30 执行，出门前检查点与用户主动请求不受影响。
  - **效果对比**：相比旧版“间隔不超过距下节课时间的 1/3、最短 30 分钟”策略，按每周 12 节课模拟，常用用户的周均刷新次数从约 85 次降至约 27 次（减少约 68%），而出门前（课前 30 分钟）的数据最大陈旧度反而从 24 分钟缩短至 10 分钟，避免了早高峰期间无意义的密集轮询。
- **优先级队列与 AIMD 预算控制**：调度器每 `SCHEDULER_TICK`（默认 30）秒运行一轮，按“主动请求（打开过期页面 / 同班同学发现调课）> 出门前检查点（距开课越近优先级越高）> 基础间隔（按数据年龄与目标间隔比值排序）”单线程串行刷新；实际发起请求前再次检查，若同轮 tick 中同班同学刚完成确认则直接跳过。全站后台请求预算 `REFRESH_BUDGET_RPS`（默认 0.65 次学校请求/秒，折合每小时约 900 次刷新；按 500 名注册用户、300 名常用用户模拟，工作日峰值约 700 次/小时）采用加性增、乘性减（AIMD）算法动态调节：一旦遇到学校服务器报错或限流立即减半，正常运行时每轮 tick 恢复上限的 10%。高负载时全站基础刷新间隔平滑拉长，处于出门前检查点的用户依然优先执行。
- **按需静默刷新**：用户打开网页、小组件或拉取日历订阅时，若本地数据年龄已超过当前目标间隔，服务端会自动将其排入后台刷新队列（同样受全站预算约束）；网页端在 2 分钟内检测到后台刷新完成后会自动静默替换为新课表，无闪烁感。
- **同班调课联动**：每次刷新后自动索引该用户的上课时间槽（`slot`：课程、教师、星期、起始节次、周次）与所修课程（课程 + 教师）。一旦某位同学刷新时发现某节课的时间、教室或周次发生变更，所有仍保存旧排课的同班同学会立即被提至刷新队列队首；若检测到**新增排课（补课 / 加课）**，则按课程索引将该门课下尚未同步该排课的同学全部提至队首。已同步新安排的同学不会重复触发联动，杜绝连锁风暴。
- **错误退避与熔断**：
  - 网络抖动或教务系统临时错误：按指数退避重试（30 分钟起，最长 24 小时封顶），连续失败达到 `REFRESH_MAX_FAILS` 次后在界面展示提醒。
  - 密码错误或登录态过期且未存密码：状态转为 `needs_rebind` 并停止自动重试，防止反复尝试导致学校账号被锁定。
  - 触发图形验证码或滑块拼图：状态转为 `captcha` 并停止自动重试，提示用户前往网页端手动登录一次。
- **上游自适应降速**：收到 HTTP 429 / 503 时按 `Retry-After` 响应头全站暂停请求（最长 10 分钟，未提供响应头则默认暂停 30 秒）；遇到 5xx、超时或连接失败时在基础最小间隔之上叠加惩罚延迟，连续出错时成倍增加（上限 60 秒），恢复正常后逐步减半。暂停期间后台刷新全面让路，用户交互式请求最长等待 10 秒，超时则友好提示“学校服务器繁忙”。
- **登录与手动刷新限流**：
  - 站点登录（每次均需访问学校 CAS）按每 IP 10 次/15 分钟、每学号 5 次/15 分钟限流。
  - 手动刷新：同一用户同一时刻仅允许一个刷新请求执行，两次手动刷新至少间隔 `MANUAL_REFRESH_MIN_GAP`（默认 20）秒；若该学期课表在 `MANUAL_REFRESH_FRESH_SECONDS`（默认 120）秒内刚成功同步过且状态正常，则直接返回已存课表，不再重复请求教务系统。后台定时刷新若发现该用户正在登录或手动刷新，会自动让出本轮。

## 建议部署在独立主机名

若将本服务部署在子路径下（如 `https://example.com/kebiao/`）与其他站点共用同一域名，在浏览器同源策略下它们属于**同一个源（Origin）**。Cookie 的 `Path=/kebiao/` 仅限制浏览器发送 Cookie 的路径范围，无法阻止同域名下其他页面的前端脚本携带 Cookie 调用 `/kebiao/api/`。若同域名下存在非你完全受控的页面，强烈建议将本服务部署在独立主机名（如 `https://kebiao.example.com`），并将 `PUBLIC_BASE_URL` 设为该根地址（无路径前缀），使会话 Cookie 作用域收敛于独立主机。

## 校历配置

将课程“第 N 周”换算为具体日历日期需要知道本学期“第 1 周周一”的日期。系统按以下优先级读取：`semesters.json`（按学期名称或学期 ID 匹配）> 教务接口 `/student/ws/semester/get/{id}` 返回的 `startDate` 等字段（自动对齐至所在周的周一）。新学期开学前只需在项目根目录的 `semesters.json` 中补充一行即可（支持热生效，无需重启服务），例如：

```json
{ "2026-2027-1": "2026-09-07", "2026-2027-2": "2027-02-22" }
```

## 开发约定

- **Python**：使用 `ruff check app tests scripts` 进行静态检查（行宽 120），使用 `pytest` 运行测试。
- **前端**：保持无构建步骤、无第三方运行时依赖；新增前端纯逻辑模块时需同步在 `tests/js/` 中补充测试，并确保 `static/js/main.js` 的模块引用图完整（`test_api.py` 会自动校验）。
- **DOM 安全**：所有新增 DOM 文本节点必须使用 `textContent` 赋值，严禁引入 `innerHTML`、`outerHTML` 或 `eval`；CSP 策略不包含 `unsafe-inline`。
- **热生效**：修改前端静态资源后直接刷新浏览器即可生效；修改 Python 代码或环境变量可通过 `/admin` 页“热重载”按钮、`systemctl reload kebiao` 或重启服务生效。

## 局限说明

- **通知渠道**：服务端仅提供站内横幅提示与邮件通知，未接入微信或商业推送通道；课前提醒由 iOS Scriptable 小组件或安卓 App 在手机本地通过系统通知/闹钟直接触发，不经过服务端下发。
- **数据库**：默认采用 SQLite（WAL 模式），足以支撑单机部署需求；如需迁移至 PostgreSQL，仅需调整 `db.py` 中的连接池与少量 SQL 语句（`ON CONFLICT` 语法两端通用）。
- **网页离线缓存**：Web 前端未注册 Service Worker 离线缓存，每次打开网页均从服务端拉取最新课表；离线查看课表请使用 iOS 小组件、安卓 App 或系统日历订阅。
